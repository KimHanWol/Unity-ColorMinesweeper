# Color Minesweeper

지뢰찾기처럼 단서를 보고 추론해서 칸을 칠하다 보면 숨겨진 도트 그림이 완성되는 모바일 퍼즐.

## 규칙

- 판 전체가 숨겨진 도트 그림이다. 칸마다 정해진 색이 하나 있다(배경색 포함).
- 열린 칸에는 **주변 8칸의 색별 개수**가 단서로 표시된다. 배경색 개수는 나머지로 알 수 있으므로 표시하지 않는다.
- 아래 팔레트에서 색을 고르고 칸을 탭한다. 맞으면 칸이 열리며 그 칸의 단서가 새로 보이고, 틀리면 목숨(3개)이 준다.
- 주변에 배경색만 있는 칸이 열리면 지뢰찾기의 0처럼 주변이 자동으로 펼쳐진다.
- 목숨을 다 잃으면 광고를 보고 이어 하거나 처음부터 다시 한다.
- 완성하면 별 3개 중 남은 목숨만큼 받는다(광고로 이어 했으면 1개). 완성 화면의 별 게이지가 끝까지 찼다가 잃은 별만큼 깎이며 이 관계를 보여 준다.
- 모든 스테이지는 **찍지 않고 추론만으로 풀린다**. 처음부터 열려 있는 칸(givens)을 솔버로 검증해 정한다.

## 왜 이렇게 만들었나

- **Unity 6 (6000.3.8f1)**: 연출 품질과 광고 미디에이션(AdMob/LevelPlay) 지원 때문에 웹 + Capacitor 대신 골랐다.
- **퍼즐 코어는 UnityEngine 에 의존하지 않는 순수 C#** (`Assets/Scripts/Core`). Unity 없이 `dotnet test` 로 솔버와
  스테이지를 검증할 수 있게 하기 위해서다.
- **화면은 코드로 조립한다.** 씬에는 진입점만 두고 판·UI·연출을 코드로 만든다. 에디터 작업 없이 코드 리뷰로 변경을 추적하기 쉽다.
- **숫자는 픽셀 폰트 스프라이트**로 그린다. 도트 그림 게임의 톤과 맞고, 확대해도 또렷하며 폰트 에셋 의존이 없다.

## 화면과 저장

- 처음 메인 화면에서 시작하기를 누르면 튜토리얼(4x4 하트 연습 판)이 뜨고, 마치면 1번 스테이지로 이어진다. 솔버의 `Solver.Hint` 로 지금 칠할 수 있는 칸과 근거 칸을 짚어 주고
  실제 숫자로 이유를 설명한다. 설정의 튜토리얼 다시 보기로 다시 볼 수 있다.
- 메인 화면 → 스테이지 목록 → 플레이. 메인에서 이어하기(아직 못 깬 첫 스테이지)로 바로 들어갈 수 있다.
- 스테이지 이름이 곧 그림의 정답이라, 완성하기 전에는 목록과 플레이 화면 모두 `번호. ???` 로 가린다.
- 진행 기록은 기기에만 저장한다(`persistentDataPath/save.json`). 스테이지를 완성할 때만 쓰고, 판 도중의 상태는
  저장하지 않는다. 판 도중에 나가려 하면 진행 상황이 저장되지 않는다고 묻는다.
- 소리는 모두 코드로 합성한다(`Services/SoundSynth.cs`, `Sfx.cs`, `Music.cs`). 설정에서 배경음악과 효과음 볼륨을 따로 조절한다.
- 광고 배치와 빈도의 근거는 [docs/광고-수익화.md](docs/광고-수익화.md).

## 언어

- 화면 문구는 모두 `Game/Services/Loc.cs` 의 번역 표에 키로 둔다. 화면 코드에 문장을 직접 쓰지 않는다.
- 지금은 한국어와 영어. 처음 실행 때 기기 언어를 따르고(한국어가 아니면 영어), 메인·목록 화면의 설정에서 바꾼다.
- 스테이지 이름은 파일의 `names` 에 언어 코드별로 둔다(`name` 은 한국어 기본 이름).
- 일본어·중국어를 넣으려면 번역과 함께 그 글자가 있는 폰트를 추가해야 한다(동글에는 없다).

## 스테이지 형식

`Assets/Resources/Stages/*.json`. 파일 이름 순서가 스테이지 순서다.

스테이지는 네모로직처럼 **사람이 그린 실제 도트 그림**이다. 무작위로 만든 그림은 넣지 않는다
(테스트에서 솔버·생성기가 어떤 그림에도 버티는지 확인하는 용도로만 쓴다).

```json
{
  "id": "heart",
  "name": "하트",
  "background": ".",
  "palette": [
    { "key": ".", "color": "#F3EEE4" },
    { "key": "R", "color": "#E8505B" }
  ],
  "pixels": [
    ".RR.RR.",
    "RRRRRRR",
    ".RRRRR.",
    "..RRR..",
    "...R..."
  ],
  "givens": [0, 6]
}
```

- `names`(선택): 언어 코드별 이름. 예: `{ "en": "Heart" }`.
- `palette.key` 는 한 글자. `pixels` 의 각 글자가 팔레트 키다. 모든 줄 길이가 같아야 한다.
- `givens` 는 처음부터 열려 있는 칸의 인덱스(`y * width + x`). 비워 두면 게임이 시드 기반으로 생성한다.
  배포할 스테이지는 에디터 도구로 생성해 저장해 둔다.
- `logic`(선택): givens 를 고를 때 플레이어에게 요구할 가장 어려운 추론. 생략하면 `full`.

### 추론 단계와 난이도

모든 스테이지는 **한 색만 보고** 풀린다. 화면은 팔레트에서 고른 색의 숫자만 보여 주므로(배경도 하나의 색),
여러 색을 번갈아 보며 조합해야 하는 추론은 쓰지 않는다. 기억해 둔 제외 정보도 쓰지 않는다.

| logic | 추론 | 플레이어가 하는 일 |
| --- | --- | --- |
| `basic` | 순서대로 | 열린 칸 하나에서 고른 색의 남은 개수가 가려진 이웃 수와 같으면, 가려진 이웃이 모두 그 색이다. |
| `full` | 같은 색 두 단서 비교 | 가까운 두 단서의 같은 색 개수를 겹치는 칸/한쪽에만 있는 칸으로 나눠 따진다(지뢰찾기 1-2 패턴). |

스테이지 순서의 첫 기준은 **그림 색 수**다(색을 빠르게 늘리지 않는다). 1색 4x4 그림으로 시작해
2색, 3색, 4색, 5색 순으로 넘어가고, 같은 색 수 안에서는 **순서대로만 풀리는 판이 먼저**(두 단서 비교가 필요한 판은 뒤), 그 안에서 **판이 작은 것부터**,
크기가 같으면 난이도 점수 순이다. 그래서 크지만 쉬운 판은 초반 뒷부분에 온다.
처음부터 열려 있는 칸은 판의 20% 안쪽으로 제한한다(배경이 넓은 그림이 시작부터 반쯤 열리지 않게). logic 은 그림 색 1~2개면 basic,
3개 이상이면 full 로 둔다.

난이도 점수(`Core/Difficulty.cs`)는 솔버가 매 순간 가장 쉬운 추론부터 시도하며 남긴 기록으로 매긴다.
단계마다 필요한 추론(순서대로 1, 두 단서 비교 4)에, 판 크기와 색 수, 두 단서 비교가 필요한 판의 가산점을 더한다.
`StageTool sort` 가 이 순서로 파일 번호를 다시 매긴다.

### 개발용 도구

- Unity 메뉴 **Tools > Color Minesweeper > Stage Preview**: 그림 미리보기, 형식 오류, 풀이 가능 여부,
  솔버 단계별 재생, givens 생성·저장.
- Unity 없이: `dotnet run --project Tools/StageTool -- validate` / `-- generate` / `-- sort`
  (모든 스테이지 검증과 난이도 표시 / givens 채우기 / 난이도 순으로 번호 다시 매기기).
- 코어 테스트: `dotnet test Tools/CoreTests`.
- Unity 없이 게임·에디터 스크립트 컴파일 검사: `dotnet build Tools/UnityCompileCheck`
  (설치된 Unity 6 의 엔진 DLL 을 참조한다. 경로가 다르면 `-p:UnityEditorPath=...`).

## 처음 열 때

빌드 목록에 올리고 Player Settings(패키지 이름, 세로 고정)를 채운다. 씬은 비어 있어도 되고, 재생하면 `GameApp` 이 스스로 뜬다.
Unity 가 만든 `.meta` 와 `ProjectSettings/` 는 커밋한다.
