# 광고 수익화 분석

2026-09 조사. 광고 배치와 빈도 규칙(`Assets/Scripts/Core/AdPacing.cs`)의 근거를 남긴다.

## 1. 보통 어떻게 넣나

**AdMob 권장 사항 (전면 광고)**
- 판과 판 사이처럼 자연스럽게 멈추는 전환 지점에 둔다. 게임이라면 레벨 사이가 대표적인 자리다.
- 판이 끝난 직후 연타하던 손에 광고가 눌리지 않도록, 끝난 뒤 바로 띄우지 말고 텀을 두거나 전환 화면을 둔다.
- 빈도 제한은 낮게 시작해 리텐션을 보며 천천히 올린다.
- 금지·비권장: 앱 실행 직후나 종료 시 띄우기, 플레이 도중 갑자기 띄우기, 연속으로 여러 개 띄우기.

**퍼즐 장르 관행**
- 로직·퍼즐 게임은 강제 광고보다 보상형 광고와 인앱 결제 비중이 높다(대략 광고 30%, 인앱 70%).
- 전면 광고는 세션당 0~2회, 어떤 광고든 사이에 2~3분 간격을 두는 것이 흔하다.
- 보상형 광고가 광고 매출의 가장 큰 몫이고, 스스로 고르는 것이라 리텐션을 해치지 않는다.
- 광고 제거 인앱 결제(보통 1회성)를 같이 두고, 결제한 사람에게는 강제 광고를 없앤다.

**단가(eCPM, 참고치)**

| 형식 | 전 세계 상위 시장 | 한국 Android |
| --- | --- | --- |
| 보상형 | $10–30 | 약 $11.2 |
| 전면 | $4–15 | 약 $8.7 |
| 배너 | $0.1–1 | — |

Android 보상형·전면 단가는 최근 1년 사이 7~11% 내려 3년 사이 최저 수준이다. 한국은 일본·홍콩·대만과 함께 단가가 높은 시장이다.

## 2. 이 게임에 적용한 것

| 자리 | 형식 | 상태 |
| --- | --- | --- |
| 목숨을 다 잃었을 때 이어 하기 | 보상형 | AdMob 연결 |
| 힌트를 다 썼을 때 힌트 1개 받기 | 보상형 | AdMob 연결 |
| 판을 완성하고 "다음 그림"/"목록"을 누른 뒤 | 전면 | AdMob 연결 |
| 게임 화면 배너 | — | 넣지 않음. 판이 좁아지고 칸을 누르다 오터치가 난다 |

**전면 광고 빈도 규칙 (`AdPacing`)**
- 처음 3판은 광고 없음. 게임을 익히는 시간만 준다.
- 완성 2판마다 최대 1번.
- 전면 광고 사이 최소 1분 30초.
- 보상형 광고(부활, 힌트)를 본 뒤 60초는 쉰다.
- 광고 제거를 산 사람에게는 전면 광고 없음. 보상형은 스스로 고르는 것이라 남긴다.
- 플레이어가 버튼을 누른 뒤에 뜨고, 광고가 떠 있는 동안 배경음악을 끈다.

## 3. 대략의 수익 추정 (한국 Android 기준)

가정: 하루 평균 12판, 위 규칙으로 전면 약 5회/일, 보상형(부활, 힌트) 약 0.8회/일, 광고 채움률 90%.

- 전면: 5 × $8.7 / 1000 × 0.9 ≈ $0.039
- 보상형: 0.8 × $11.2 / 1000 × 0.9 ≈ $0.008
- 합계 ARPDAU ≈ **$0.047** (1일 활성 사용자 1,000명이면 하루 약 $47, 월 약 $1,400)

단가는 국가, 미디에이션, 계절에 따라 크게 흔들리므로 출시 뒤 실제 수치로 규칙을 다시 맞춘다.

## 4. AdMob 연결 방식

- 플러그인: Google Mobile Ads Unity(`com.google.ads.mobile`, OpenUPM). 필요한 Android/iOS 라이브러리는 함께 들어오는 EDM4U 가 빌드 때 받는다.
- 코드: `AdMobAds` 가 시작할 때 동의(UMP)를 받고 SDK 를 초기화한 뒤 `Ads` 의 자리 표시 광고를 실제 광고로 바꿔 끼운다.
  보상형은 자리마다(이어 하기, 힌트) 광고 단위를 따로 쓴다. 광고는 미리 불러 두고, 실패하면 5초부터 최대 2분 간격으로 다시 시도한다.
  플러그인이 없으면 `GOOGLE_MOBILE_ADS` 가 꺼져 자리 표시 광고만 쓴다.
- ID: `AdMobConfig` 한 곳에만 넣는다. 에디터와 개발 빌드는 늘 구글 테스트 ID를 쓰고, 출시 빌드에서 실제 ID가 있을 때만 실제 광고를 쓴다.
  앱 ID는 `AdMobSetup`(에디터)이 플러그인 설정 파일(`Assets/GoogleMobileAds/Resources`)에 옮겨 적는다. 앱 ID가 비면 안드로이드 앱이 바로 꺼지므로 실제 ID가 없으면 테스트 앱 ID를 넣는다.
- 출시 전 할 일: AdMob 에서 앱과 광고 단위(`rewarded_revive`, `rewarded_hint`, `interstitial_stage_clear`)를 만들어 `AdMobConfig` 에 넣고,
  스토어 등록 뒤 app-ads.txt 를 개발자 웹사이트에 올린다. Play Console 데이터 보안에 광고 ID 수집을 표시한다.

## 5. 다음에 할 것

1. **미디에이션**: 트래픽이 생기면 AdMob 미디에이션(또는 LevelPlay)으로 네트워크를 경쟁시켜 단가를 올린다.
2. **힌트 재화 조정**: 처음 3개, 광고 한 번에 1개. 출시 뒤 힌트 광고 시청 수와 이탈을 보고 개수를 맞춘다. 인앱으로 힌트 묶음을 파는 것도 후보다.
3. **광고 제거 인앱 결제**: `Ads.AdsRemoved` 플래그는 준비되어 있다. Unity IAP 를 붙여 결제 완료 시 켠다.
4. **아동 대상 여부**: 가족 정책 대상으로 등록하면 광고 형식과 네트워크가 제한된다. 대상 연령을 정한 뒤 설정한다.
